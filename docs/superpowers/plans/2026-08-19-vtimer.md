# vTimer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `vTimer` form component for date, datetime-local, and time values with the same public API conventions as the existing form components.

**Architecture:** Implement `VTimer` as a focused `HtmlElementNode` input component in the existing compact components module. Reuse the established value/state/setup patterns, register `vTimer` through the existing child-factory mechanism, and demonstrate it in the current components page.

**Tech Stack:** JavaScript ES modules, Vitest, jsdom, Vite.

## Global Constraints

- Preserve native `input()` semantics; the compound component is named `vTimer` / `VTimer`.
- Support exactly `date`, `datetime-local`, and `time`, defaulting invalid or empty modes to `date`.
- Support value read/write, disabled, readonly, required, and the existing event API.
- Export the public factory and class, register `parent.vTimer()`, and avoid new dependencies.
- Assert public DOM behavior rather than private fields.
