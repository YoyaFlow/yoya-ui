# vSidebar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an accessible, collapsible, responsive `vSidebar` component that composes the existing menu group, submenu, and active-item primitives, with categorized demos and generated source.

**Architecture:** `VSidebar` will be a compound `<aside>` component in the existing components module. It owns a title, a native-button toggle, and one `VMenu`; navigation groups, nested items, current-route state, and roving focus remain delegated to the established menu components. Responsive behavior uses an opt-in `matchMedia` listener that drives the same public `collapsed()` state and is removed by `destroy()`.

**Tech Stack:** Vanilla JavaScript ES modules, yoya-ui `ViewNode`/`HtmlElementNode`, Vitest + jsdom, Vite, ESLint, Prettier.

## Global Constraints

- Every reusable demo uses `function ComponentName(options) { return { render() { return viewNode; } }; }`.
- Demo source panels reuse `examples/components/component-source.js`; no duplicate source strings.
- Component objects are composed through `child(componentObject)`.
- Demo files stay organized by broad category; `vSidebar` belongs to navigation.
- Preserve unrelated dirty-worktree changes and selectively stage only this task's hunks/files.
- Use test-first RED/GREEN cycles for each behavior.
