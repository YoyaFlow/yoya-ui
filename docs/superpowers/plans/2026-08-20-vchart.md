# vChart Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a library-agnostic `vChart` host that initializes, updates, resizes, and destroys an optional chart adapter without bundling a chart library.

**Architecture:** `VChart` extends `HtmlElementNode` and renders a stable `.yoya-vchart` host element. An adapter receives `init(host, context)`, `update(instance, context)`, `resize(instance, context)`, and `destroy(instance, context)` callbacks; the host owns only adapter lifecycle and data/options state. The components demo adds a lightweight adapter-driven card to the data-display category and generates its source through `ComponentSource`.

**Tech Stack:** JavaScript ES modules, existing ViewNode/HTML DSL, Vitest with jsdom, Vite examples, ESLint, Prettier.

## Global Constraints

- No ECharts or other chart library is added to production dependencies.
- Every demo uses the standard object-component function pattern.
- Demo source is generated from the component function through `ComponentSource`.

**Interfaces:**

- `adapter.resize(instance, context)` receives `{ width, height }`.
