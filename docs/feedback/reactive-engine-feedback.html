1. 区域重建：明确「弃建」协议，解法齐备 基础库 不成立（换形态）

当前情况

  • rebuild() 清空子节点并重跑 setup：旧子树销毁、新子树新建，成功后才替换 DOM；失败自动回滚保旧内容。
  • 区域宿主元素身份保留，子树内元素身份不保留：焦点、光标、选区、滚动、iframe、媒体播放、CSS 过渡随重建丢失。
  • 这是写进文档的显式协议，并被 region-flush 测试锁定：flush 后元素身份不变，rebuild 后身份改变。

当前已提供的解决方案

  • 值绑定原地更新：signal 句柄传进 attr / style / vText，写入只改值、不重建 DOM、不丢焦点。
  • 放弃 rebuildable，动态值控制显隐：结构不变的显示 / 隐藏场景，直接 style('display', signal)、style('visibility', signal)、attr('aria-hidden', signal)——身份天然保持，无需任何额外处理。
  • 谓词延迟：rebuildable(predicate) 为假时只 flush 值绑定，结构原样保留。
  • 预制节点挂载：节点先创建、句柄先持有，再挂进主结构，身份跟着句柄走。
  • 结构边界外置：播放器、第三方实例等长生命周期内容放区域之外。

「收养式局部协调」是 vDOM diff 为保住隐式身份被迫发明的机制：模板框架里节点身份只能靠树比对推断。纯 JS 模式下身份由 ViewNode 句柄显式持有，保身份就是继续用同一个节点改值——不需要额外处理。

2. 信号传播：同步级联，batch 的边界已实测 基础库 部分成立

当前情况（实验验证）

  • 默认引擎为内化 @preact/signals-core，写入同步传播，无自动微任务批处理。
  • 区域同时订阅 a、b 两个信号，一次事件连续写两个 → 重建 2 次。
  • 包进 batch() → 仍是 2 次：每个依赖信号各有一条独立订阅，batch 只合并「同一信号的多次写入」。
  • batch 的真实收益：通知推迟到批结束，第一次重建读到的已是全部终值，不提交中间态。

当前已提供的解决方案

  • 一次事件里的多个写点收进同一处理器并包 batch()——消除中间态提交，首重建即见终值。
  • DevTools 的 region 事件（trigger: 'signal'）直接计数核对重建行为。
  • 值绑定按「值未变不写 DOM」提交，刷新幂等。

3. computed 菱形：由引擎天然支持，当前没有此问题 基础库 不成立（引擎已支持）

当前情况（实验验证）

  • A→(B,C)→D 菱形：a 变更后，d 的订阅者只收到一次终值，无中间值。
  • 一致性由内置引擎天然支持：效果通知分代调度——B / C 先重算，D 排在其后，求值时两个输入都已是新值。
  • 这不是需要使用者绕开的边界，而是引擎当前直接提供的行为。

当前已提供的解决方案

  • 直接用 computed 组合任意菱形依赖即可，无需额外处理——一致性由引擎保证。
  • 派生链可任意分层（惰性求值 + 缓存），下游绑定与区域只读终值。

4. 列表协调：纯 JS 模式下理应如此 设计如此 不成立（旧直觉化石）

当前情况

  • 评审预设「框架必须内建 keyed diff / move」——那是模板 + vDOM 框架的问题：模板把结构变化藏进框架，协调语义只能由框架猜测。
  • yoya 是纯 JS 声明式构建：forEach / map 循环就是 v-for，if / 三元就是 v-if，结构怎么变代码就怎么写，没有隐藏语义。
  • 基础库已提供子节点操作原语，key 唯一性校验、data-row-key 镜像、DOM 身份保留均有测试锁定；区域重建时 keyed 子节点重跑不报重复 key。
  • 演示与测试都有体积：StateKeyedExample1 演示追加 / 移除完整交互，definition-complex 用 task.id 做 key 组装任务行，core 侧 keyed / region / devtools 测试均覆盖。

当前已提供的解决方案（标准用法）

  • addChild(key, node)：挂载并登记唯一 key。
  • getChild(key)：按 key 复用。
  • removeChild(key)：删除单个子节点并销毁，不碰兄弟。
  • 预制节点挂载：节点先创建、句柄先持有，再挂进主结构——身份跟着 JS 对象走。
const list = div();
const row = div((line) => line.text('第一行')); // 预制节点：句柄在手

list.addChild('r1', row);   // 挂载进主结构，身份由 ViewNode 句柄持有
list.getChild('r1');        // 复用
list.removeChild('r1');     // 删除单个子节点（增量，不碰兄弟）

排序 / 过滤场景在循环里用 addChild / removeChild 增量协调即可；把可变列表放进 rebuildable 区域任其整树重跑，才会出现「丢状态」——那是用法问题，不是库缺口。组件各自的选择互不构成库层欠账：vTable 清空重建是「简单数据驱动优先」的实现选择，tree-table 展开折叠保留行身份，说明同一套原语组件随时可自管。

5. 错误处理：三层能力，两层已提供 基础库 + 异步组件 部分成立

当前情况

  • 基础库（已有）：区域 rebuild 先构建成功再替换，抛错自动回滚、旧内容保留。没有魔法——重跑的是使用方写的 builder，异常从业务代码抛出、原样 re-throw，报错位置（stack）就是业务代码位置。
  • 异步组件（已有）：vDynamicLoader 内建 loading / error 状态、retry() 与竞态代守卫（generation），错误就是组件状态的一部分；echart / three 各自内部 try/catch 降级。
  • 当前边界：同步渲染期的意外异常（初始构建、非区域节点抛错）无通用隔离层，页面级兜底目前是使用方职责。

当前已提供的解决方案

  • 区域内可恢复更新直接依赖 rebuild 回滚——异常即业务异常，定位零成本。
  • 异步数据 / 动态加载场景用 vDynamicLoader：loading / error / retry 都是正常 UI 状态，错误纳入状态流展示。
  • 请求层错误统一走 Result / configureRequest 语义（ok=false 抛错，错误带 code / showType）。

6. 过渡与页面缓存：vTransition + RouterViews 已覆盖 组件 不成立（换形态）

当前情况

  • vTransition 是保身份的 show / hide 过渡：同一元素切 enter / leave class（或 WAAPI），尊重 prefers-reduced-motion，SSR toHTML 安全，destroy 取消动画。
  • 页面缓存由 RouterViews 天然提供：vRouterViews 是多标签工作区——打开的页面以标签保持，切换不关闭；标签列表（paths）与激活页（activePath）持久化到 localStorage（persist 默认开启，可配 storageKey），刷新后 restoreTabs 恢复整个工作区；配合路由 query / params，列表筛选状态编码在 URL 里随标签保留，回到标签即回到同一数据视图。
  • 当前边界（如实）：无列表 move 过渡组件、无跨内容 out-in 模式；区域重建会中断区域内动画（弃建协议的直接后果）。

当前已提供的解决方案

  • 显示 / 隐藏动画直接用 vTransition：show() / enter() / leave() / toggle()，duration 与 motion 可配。
  • 后台列表页缓存直接用 vRouterViews：标签保持打开 + 工作区持久化 + 刷新恢复，筛选状态走 URL query。
  • DOM 级保活用预制节点 + 动态 style / attr 显隐（第 1 条的标准解法），节点身份与内部状态保持。

6.5 hydration 失配：已有可观测性 基础库 基本已有

当前情况

  • hydrate 是收养式：adoptElement 逐节点对齐服务端 DOM，匹配则收养（不重建元素）。
  • 失配（标签 / 节点类型不一致）时替换节点并上报 hydrate-mismatch devtools 事件：expected / existing 可读名（如 div vs span、#text vs em）+ ViewNode 引用。
  • 事件只在 devtools 开启时上报，生产路径零开销、静默替换。
  • 测试覆盖：标签失配、文本槽失配、匹配时保持安静。

当前已提供的解决方案

  • 开发期开 enableDevtools() 并订阅 hydrate-mismatch 事件，拿 expected / existing 与节点引用直接定位。
  • 两端确定性由 SSR 纪律保证：render / toHTML 不读 document / window、不用随机值，hydrate 前提写进文档。

验证方式

  • ✓ 区域重建身份：region-flush 测试断言 flush 后同一元素、rebuild 后不同元素。
  • ✓ 信号传播：devtools region 事件计数探针实验——同步连写两信号重建 2 次，batch 下仍 2 次、首重建即见终值。
  • ✓ computed 菱形：探针实验——a 变更后 d 的订阅者只收到一次终值，无中间值。
  • ✓ keyed 原语：keyed-child 测试锁定 key 唯一性、身份保留、data-row-key 镜像；region 测试锁定重跑不报重复 key。
  • ✓ 错误回滚：rebuild 的 catch 路径源码审读——构建失败恢复旧子树、原样 re-throw。
  • ✓ hydration 失配：hydrate-mismatch 测试覆盖三类场景（标签失配 / 文本槽失配 / 匹配安静）。
