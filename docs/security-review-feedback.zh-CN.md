# 安全评审反馈

本页回应一份外部 AI 安全评审对 yoya-ui 提出的四条问题：其中两条对本库不成立，
一条方向错了，一条属实但不属于安全问题。最后两节列出评审确实带出的改动，以及
库的默认行为。

一句话版本：**这里的转义是默认行为，而不是交给使用方的任务。** 文本、属性与
行内样式在视图树序列化时都会转义，SSR 的状态脚本也把 `<` 转义，无法从
`<script>` 里逃逸出来。

## 逐条结论

| 评审原说法                                    | 结论                   | 依据                                                                                                                                                                                                          |
| --------------------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| i18n `{name}` 插值可能注入恶意内容            | 对 HTML 输出不成立     | 插值确实不转义（[i18n.js](../src/core/i18n.js)），但结果落进文本节点，`VTextNode.toHTML()` 会转义（[node.js](../src/core/node.js)）；DOM 路径走 `textContent` / `setAttribute`                                |
| SSR XSS：未过滤用户输入，建议启用模板引擎转义 | 不成立，且建议无对应物 | 本库没有模板引擎。SSR 输出由节点树生成：文本与属性均转义，页面壳 id/lang 走 `escapeHtmlAttribute`，`serializeState()` 做 `JSON.stringify(...).replace(/</g, '\\u003c')`（[ssr.js](../src/core/ssr.js)）       |
| 权限字符串裸码易被猜测/伪造                   | 方向错了               | 前端权限只是体验层，项目文档已写明（[access-control.zh-CN.md](access-control.zh-CN.md)）。授权集合由服务端下发的 `createAccess({ permissions })` 决定，猜到一个码不等于拥有它；前端枚举校验也拦不住改 JS 的人 |
| `on('click')` 未做节流防抖                    | 属实，但不是安全问题   | `.on()` 转发原生事件，同一节点同一事件只保留最新 handler，`destroy()` 自动清理。节流是业务策略，框架默认加会改变语义（连点计数、提交按钮）                                                                    |

## 评审确实带出的改动

1. **`vTree` 的 toggle 图标把字符串当 HTML 解析。** `toggleIcon()` 的入参类型是
   `ChildInput`，但字符串被送进 `template.innerHTML`，于是
   `toggleIcon('<b>▸</b>')` 会生成真实标签，与「字符串即文本」的类型语义不符。
   现在字符串按文本渲染，需要自定义图标请传节点；回归用例见
   [tree.test.js](../src/data-display/tree.test.js)。
2. **演示里用 `innerHTML` 拼行内容。** AG Grid HR 演示原先拼 `<b>${row.name}</b>`
   字符串，现在改为创建元素 + `textContent`，避免这个写法被复制到渲染真实数据的
   代码里。

## 转义对照

| 位置                          | 处理方式                                                             |
| ----------------------------- | -------------------------------------------------------------------- |
| 文本（含 i18n）               | `VTextNode.toHTML()` → `escapeHtml`；DOM 路径写真实文本节点          |
| 属性                          | DOM 路径用 `setAttribute`；序列化时转义属性值                        |
| 行内样式                      | 序列化时转义                                                         |
| SSR 页面壳（`id`、`lang` 等） | `escapeHtmlAttribute`                                                |
| 序列化的请求状态              | `JSON.stringify(...).replace(/</g, '\\u003c')`，`</script>` 无法逃逸 |

真正的 raw HTML 只来自使用方自己引入的通道：自己写的 `innerHTML`，以及三方富文本
编辑器（Quill 这类）——它们的内容本来就是 HTML。yoya-ui 不会把用户数据交给这些通道。

## 权限口径

客户端的 `access` 声明决定**界面显隐与控件是否可编辑**，它不是授权边界：真正需要
保护的操作必须由服务端校验每个请求。未声明 `access` 的节点永远放行（fail-open），
因此不声明就没有任何行为变化。
