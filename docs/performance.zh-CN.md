# 性能基准（官方 js-framework-benchmark）

这一页放的是 yoya-ui 在官方 [js-framework-benchmark](https://github.com/krausest/js-framework-benchmark)
（`keyed` 分类）上的实测数字：**AST 编译版（`yoya-ui-ast`）**对比官方原生基线 `vanillajs`，
同时并列对照条目（同轮测量：运行期版 `yoya-ui-runtime`、Vue、React、Solid、Svelte），
便于看改动带来的位移与横向位置。报告页里 yoya 更快/更慢的格子有底色区分（±5% 内视作持平）。

数字不是手写的：表格块由 `benchmark/results.json` 生成，
`npm run report:bench:write` 刷新、`npm run verify:dist` 校验，手工改数字会直接失败。
复跑步骤见 [benchmark/README.md](../benchmark/README.md)。

## 怎么读

- **script / paint 拆解**：官方 runner 把每次操作拆成 JS 执行（script）与渲染（layout / paint / commit）。
  yoya-ui 的绘制桶除 `07` 外都与原生基线持平（`01`～`06` / `08` / `09` 差 −1.7～+1.8 ms，落在噪声内），
  剩余差距是 script 桶、`07` 那一格的绘制差与内存。
- **create 类操作是主战场**：`01 / 07 / 08` 三项的 script 差距最大（1k 行 +3.5 ms、10k 行 +41.1 ms），
  对应节点对象构造、登记与首次写 DOM 的成本；`03 / 04 / 05 / 06` 这类增量操作已经追平甚至反超原生
  （`03` 21.3 ms vs 原生 22.8 ms，`04` 6.0 ms vs 原生 6.8 ms）。
- **清空路径是剩下的稳定差距**：`09_clear1k_x8` 20.3 ms，原生 14.7 ms（script 18.6 ms vs 11.3 ms），
  这是销毁路径改单趟 + 批量摘除之后的残余成本（改之前是 58 ms）。
- **`04` / `03` 反映的还有条目自身的状态模型**：yoya 条目用共享 `selectedId` 派生每行的选中类
  （`computed(() => selectedId.value === row.id)`），一次点击会唤醒全部行——与 Vue 条目的
  `:class` + `v-memo` 同形；React 条目把选中态按行传入并用 `memo` 比较；只有手写的原生基线只碰
  受影响的两行。看 `04` 这一格时要记得这一点；O(1) 的替代建模见 `docs/component-authoring.zh-CN.md` §6.2。
- **内存仍是最大量级差**：建 1000 行后 4.15 MB vs 原生 2.46 MB（1.69×）；剩余部分主要是 DOM 对象与
  V8 节点对象头。
- **体积是已知代价**：单页体积 83.4 KB / 22.3 KB brotli vs 原生 11.7 KB / 2.5 KB brotli，这是
  「一套 DSL + 组件库」与「手写 DOM 调用」的固有差别（编译版条目把片段与运行期钩子一起打进产物）。
  两套条目都把业务代码的核心入口 `@yoyaflow/yoya-ui/core` 别名到 `@yoyaflow/yoya-core`，让业务代码与
  编译产物共用同一份运行期实例——编译版因此只比运行期版大 ~4%（83.4 KB vs 80.6 KB）。少了这条别名，
  产物里会带**两份运行期**（145.6 KB，+76%），编译出来的行也会订阅在第二个信号实例上；口径见
  [benchmark/README.md](../benchmark/README.md)。
- **first paint 是单次采样**：官方 runner 只采一次，本机多次重复的实测区间约 355～920 ms
  （本轮 357.4 ms），表里那一格不要当精确值看；它也因此不适合用来判断 KB 级体积变化。

## 跨口径不可比

开发期还用过一套自建 harness（msedge headless，按 1000 行的 MB 增量取数）做改动前后的同机对照，
脚本属于一次性的工作现场（`.scratch/`，已随 2026-09-25 的清理删除；需要复跑就照这里的口径重写）。
**两套口径的绝对值不可互换**：官方 runner 用的是 Chrome for Testing 152 + playwright、按操作计时；
自建口径直接读 `performance.measureUserAgentSpecificMemory()` 的行增量。
同一份代码在两套口径下的读数差可达 1.5～3 倍，所以对比只能在口径内纵向进行。
