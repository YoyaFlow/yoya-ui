# yoya-ui 核心基准（js-framework-benchmark 口径）· 口径定稿

本文件是基准测试的唯一口径来源。所有运行、报告与护栏都以它为准；改口径先改这里。

## 1. 定位与边界

- **测什么**：yoya-ui 核心能力——keyed 行对账、值位置句柄绑定、虚拟滚动、SSR/hydration、组件层开销。
- **不测什么**：业务组件细节（表单校验、弹窗、主题）、网络与 i18n 文案量；**不测区域重建**——"重建比原地更新慢、且随数据量变差"是已知结论，不需要基准来证明。
- **对外可比性**：本仓库**只做内部报告，不提交上游 PR**。上游项目（krausest/js-framework-benchmark）仅作为**操作集合与 DOM 契约**的参考，保证我们的实现形态与之一致，便于未来需要时对接。

## 2. 操作与实现映射

九个标准操作，yoya-ui 用**惯用写法**实现（不为了数字改写法）：

| 操作              | 实现                                          | 备注                       |
| ----------------- | --------------------------------------------- | -------------------------- |
| create 1,000      | `keyed()` 一次性写入 1,000 行数据             | 行模型：`id` + 标签句柄    |
| replace all       | 换整批行引用（新的行对象）                    | 不放水成"原地改字段"       |
| update every 10th | 行内**字段句柄**写入（`label` 句柄 + ` !!!`） | 快路径：不应发生任何行重建 |
| select row        | 点击行 → 选中态由句柄驱动（`danger` 类）      | 一次写入，只有相关行改类   |
| swap rows         | 交换第 2 行与第 999 行（索引 1 与 998）       | 身份保持移动               |
| remove row        | 点击行的 `.remove` → 从数据移除该行           | 成员销毁与解绑             |
| create 10,000     | 全量 DOM，真实插入 10,000 行                  | 与上游同口径               |
| append 1,000      | 追加 1,000 行                                 | 既有行不得重建             |
| clear             | 数据置空                                      | 批量销毁与 GC              |

行内容约定：id 列为行 id（1 起）；标签列初始为 `label <id>`，被 update 命中后追加 ` !!!`。选中行为 `danger` 类。

## 3. 两档大规模与缩放研究

大规模**拆成两条独立结论**，不放在同一栏比较：

| 条目                      | 口径                               | 可比性                                                   |
| ------------------------- | ---------------------------------- | -------------------------------------------------------- |
| create 10,000（全量 DOM） | 真实插入 10,000 个行节点           | **与上游可比**                                           |
| 10,000 逻辑行（虚拟滚动） | 逻辑行 10,000，真实 DOM 约百余节点 | **仅内部可比**：问的是"省了什么、代价在哪"，不是"插得快" |

虚拟滚动档测：真实 DOM 节点数、首屏可见耗时、跳转到远端行耗时、滚动期间长任务、堆占用。
**缩放研究**：逻辑行 1k / 10k / 100k，看首屏、堆、跳转是否近似平坦。
**操作子集**：虚拟滚动档只跑语义成立的操作（追加 / 替换 / 改可见行 / 跳转 / 滚动）；swap 远端行、删除远端行、每第 10 行更新只在全量档跑。
报告写法固定为「N 逻辑行（真实 DOM M 节点）」，两个数都写。

## 4. 指标

术语：**核心库基础元素**指本库 `core` 层的 HTML 元素工厂（`tr/td/a/span` 等），**UI 库组件元素**指 `ui` 层的官方组件（`vTable/vTr/vTd` 等）；两者都是本库能力。做组件层对照时，核心库一列是**对照基线**（用来看 UI 组件层多付多少），不是"库外写法"。

### 4.1 时长

- 口径：点击 → DOM 稳定后的绘制（页内 `performance.now()`，rAF 收敛判定），不是 Node 侧包一圈。
- 轮次：预热 3 轮（不计入）+ 测量 15 轮（可用参数覆盖）。
- 聚合：**中位数**、**p95**、**IQR**；保留每轮原始耗时。
- 环境：Chromium 系浏览器 headless（优先 `chrome`，本机回退 `msedge`），记录浏览器与版本、平台、CPU 核数、Node 版本、仓库版本与提交。**跨机器、跨浏览器版本的数字不比较**。

### 4.2 内存

- 采样点：初始 / 1k / 10k / clear 后 / 连续 10 轮 replace 后。
- 关键派生：**clear 后未回落量**（泄漏信号）、10 轮 replace 后的增量。
- 测量方式：优先 `measureUserAgentSpecificMemory()`，回退 `performance.memory.usedJSHeapSize`（需 `--enable-precise-memory-info`）；不可用时报告里标注"该项不可用"。

### 4.3 体积

直接引用现有产物报表的数字（core / ui / full 入口 min+gzip），**不在基准里重测**，避免两套口径。

### 4.4 启动

- 客户端 `bindTo()` 挂载：导航开始到 ready、到首次绘制。
- SSR + `hydrateOrMount()`：服务端渲染耗时与客户端接管耗时分开记录。

## 5. 确定性护栏（硬门禁）

时间指标只做软告警；下面这些是**硬失败**项，用于拦住"快路径被悄悄换成重建"：

1. update every 10th：行构建调用次数为 **0**；
2. 每个操作的 DOM mutation 数量与预期量级一致（例如 update 约等于命中行数，而不是整表）；
3. swap rows / append 1,000 后，**既有行节点身份不变**；
4. 每个操作后 DOM 行数、id 列与标签内容与期望数据一致。

护栏不需要浏览器时间测量即可快速运行（秒级），失败信息要指出"哪条护栏、哪个操作、实际值与期望值"。

## 6. 运行与归档

- 运行：`npm run bench:jfb`（可 `--op` / `--runs` / `--variant` 限定）；前置为 `npm run build`（基准页引用产物入口）。
- 结果：
  - `benchmarks/results/latest.json`：最近一次运行（不入库）；
  - `benchmarks/results/baseline.json`：基线（入库，作为报告表格的数据源，可用 `--write-baseline` 刷新）；
  - 报告：由基线生成 `docs/benchmarks.md` 与 `docs/benchmarks.zh-CN.md`，由门禁校验"表格与 JSON 一致"，不允许手工改数字。
- 例行：夜间跑基准 + 归档产物；护栏违反硬失败，时间类指标仅同机同版本相对告警（>20%）。基准不进 PR 触发（噪声与耗时）。
- 噪声控制：IQR 超过中位数一半时该操作标记为"噪声偏高"，**不允许**用这种运行覆盖基线（需 `--allow-noisy`）；每个操作开始前强制 GC 一次，轮次之间不强制（每轮强制会因冷堆重新增长而制造主 GC 停顿，实测方差更大）。
- 更新基线后要跑一次 `npm run format`：结果 JSON 会被 Prettier 重排，未格式化的文件会被 `format:check` 拦下。

## 7. 报告要写清的三件事

1. 跨机器不可比；插件式指标（组件层开销、虚拟滚动）仅内部可比。
2. 虚拟滚动档"逻辑行数 ≠ DOM 节点数"，两个数都给出。
3. 体积口径来自产物报表，不是基准自测。
